# 拾词输入法：获取与发布

Android 与 Windows 共用项目主页，分别编号、验证和发布。这里按平台提供入口，不把一个平台的新版当作另一个平台的下载。

## Android

**开发预览，尚无公开 APK 下载。** 想现在试用，可以在 Windows x64 电脑上按 [Android 构建说明](../android/README.md#构建环境)自行构建。当前最低系统版本为 Android 10，支持 `arm64-v8a` 和 `x86_64`。

1. 按构建说明完成 `prepare` 和 `apk`，得到 `android/app/build/outputs/apk/release/app-release.apk`。这是本地开发签名，不是商店发行包。不同签名的包不能直接覆盖安装；不要为了升级就卸载有本地词频数据的版本。
2. 在测试设备上安装自己构建的 APK，打开「拾词」，依次点「启用拾词」和「切换键盘」，在系统选择框里选拾词。
3. 回到拾词点「试打几句」。用全拼输入 `jiejue`，点「解决」应输入中文；长按同一候选应打开英文详情，不会直接提交英文。

词库仍是开发数据，未获人工发布审批。兼容性和性能以[对应构建的验证记录](android-validation.md)为准，不以其他分支或旧 APK 的结果代替。

## Windows

**Windows 11 x64 实验版，暂不提供公开安装包。** 如需研究 Windows 端，请从[打包记录](packaging.md)和[已安装环境的验收记录](installed-desktop-acceptance.md)开始。Windows 端后续独立发布，不要求 Android 等待。

## 维护者：首次公开发布

- **分开打标签。** Android 使用 `android-v<versionName>`，Windows 使用 `windows-v<产品版本>`。首次 Android 公测标为 **Pre-release**；只上传这一端的产物。发布成功后，将上面对应平台的状态更新为该标签 Release 的链接，而非整个仓库的 `latest`。
- **先整合，再验证。** 从临时整合分支的干净提交构建，验证版本号、词库、中文选词、英文提交、剪贴板、键盘重开和密码框；分别记录真机与模拟器的实测和未测范围。通过后才将 `codex/android-dev` 快进到已验证的提交。按[开发包交付流程](../android/README.md#交付开发包)导出与同一提交对应的 APK、项目与原生依赖源码、签名信息及记录。公开标签须指向对应源码提交，不能换包沿用旧报告。
- **核对公开范围。** 源码归档会包含提交中跟踪的文件。公开仓库历史、源码包和验证材料都要检查：尤其是设计参考图的授权、词库及字体的署名、报告和截图中的本机路径与设备标识。未厘清的不直接公开；不上传签名私钥，也不以预发布标记代替审核。
- **核对用户实际下载的文件。** 将 APK 对照交付 `manifest.json` 中的 `apkSha256`，在 Release 说明中列出 SHA-256、签名证书指纹、支持的 Android 版本／架构、实测范围及已知限制，再更新首页入口。Windows 未就绪时不创建 Windows Release。

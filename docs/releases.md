# 拾词输入法：获取与发布

Android 与 Windows 共用项目主页，分别编号、验证和发布。这里按平台提供入口，不把一个平台的新版当作另一个平台的下载。

## Android

**开发预览，尚无公开 APK 下载。** 想现在试用，可以在 Windows x64 电脑上按 [Android 构建说明](../android/README.md#构建环境)自行构建。当前最低系统版本为 Android 10，支持 `arm64-v8a` 和 `x86_64`。

1. 按构建说明完成 `prepare` 和 `apk`，得到 `android/app/build/outputs/apk/release/app-release.apk`。这是本地开发签名，不是商店发行包。不同签名的包不能直接覆盖安装；不要为了升级就卸载有本地词频数据的版本。
2. 在测试设备上安装自己构建的 APK，打开「拾词」，依次点「启用拾词」和「切换键盘」，在系统选择框里选拾词。
3. 回到拾词点「试打几句」。用全拼输入 `jiejue`，点「解决」应输入中文；长按同一候选应打开英文详情，不会直接提交英文。

Android 公开预览沿用 AI 语义审校，并核对固定快照、来源署名及自动引擎回归，不要求逐条人工复审。词义仍可能有误，欢迎反馈。兼容性和性能以[对应构建的验证记录](android-validation.md)为准，不以其他分支或旧 APK 的结果代替。

## Windows

**Windows 11 x64 实验版，暂不提供公开安装包。** 如需研究 Windows 端，请从[打包记录](packaging.md)和[已安装环境的验收记录](installed-desktop-acceptance.md)开始。Windows 端后续独立发布，不要求 Android 等待。

## 维护者：首次公开发布

1. **完成 Android 预览检查。** 先在 `codex/android-preview3-integration` 验证模拟器安装和启动、中英文提交、键盘重开及密码框剪贴板保护；区分产品问题和自动化失败，确认的核心崩溃或隐私问题先修。维护者日常自用和自动化结果分别记录；正式真机回归安排在预览发布后，不作为首发前置条件。
2. **收口本地开发线。** 上述检查通过后，将 `codex/android-dev` 快进到已验证的提交；本次不单独推送开发分支，也不合入 Windows 开发分支。
3. **保留经核对的提交历史。** 核对拟公开的文件和可达历史，包括设计参考图和其他第三方材料的分发条件、署名、密钥及本机信息。核对通过后，从已验证的提交正常创建 `main`，保留原提交及 SHA。维护者同意将已浏览的 61 张 Windows 验收截图随历史公开，不为这批图重写历史。若发现必须排除的内容，只在独立公开副本里处理，保留本地原历史。词库不等人工复审，但仍须核对来源和再分发条件。
4. **构建并发布同一版本。** 从公开候选提交构建，使用[独立发行签名并复验最终 APK](android-public-preview.md)。对齐签名、SHA-256、源码与原生依赖源码；私钥不上传，未批准公开的原始验收报告不作为发布附件。只推送 `main` 和指向对应提交的 `android-v<versionName>` 标签，GitHub 先建草稿再发 **Pre-release**；注明兼容范围、已知限制和真机待补验。发布后将首页指向对应标签的 Release，不指向整个仓库的 `latest`。Windows 不创建 Release，之后独立使用 `windows-v<产品版本>`。

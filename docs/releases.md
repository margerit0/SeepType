# 拾词输入法：获取与发布

Android 与 Windows 共用项目主页，分别编号、验证和发布。这里按平台提供入口，不把一个平台的新版当作另一个平台的下载。

## Android

**公开预览：[下载 0.1.0-preview.6](https://github.com/margerit0/SeepType/releases/tag/android-v0.1.0-preview.6)。** 最低系统版本为 Android 10，支持 `arm64-v8a` 和 `x86_64`。从 GitHub 发行版 `preview.5` 可覆盖升级。

1. 从发布页下载已签名的 APK。若已安装同包名但签名不同的开发版本，不能直接覆盖安装；不要为了试用就卸载有本地词频数据的版本。
2. 在测试设备上安装 APK，打开「SeepType」，依次点「启用拾词」和「切换键盘」，在系统选择框里选 SeepType。
3. 回到拾词点「试打几句」。用全拼输入 `jiejue`，点「解决」应输入中文；长按同一候选应打开英文详情，不会直接提交英文。

Android 公开预览沿用 AI 语义审校，并核对固定快照、来源署名及自动引擎回归，不要求逐条人工复审。词义仍可能有误，欢迎反馈。本版签名 APK 的验证范围见发布说明，不以其他分支或旧 APK 的结果代替。

也可以在 Windows x64 电脑上按 [Android 构建说明](../android/README.md#构建环境)自行构建；默认生成的是本地开发签名 APK，不是发布页提供的发行签名 APK。

## Windows

**Windows 11 x64 实验版，暂不提供公开安装包。** 如需研究 Windows 端，请从[打包记录](packaging.md)和[已安装环境的验收记录](installed-desktop-acceptance.md)开始。Windows 端后续独立发布，不要求 Android 等待。

## 维护者：首次公开发布

1. **完成 Android 预览检查。** 先在 `codex/android-preview3-integration` 验证模拟器安装和启动、中英文提交、键盘重开及密码框剪贴板保护；区分产品问题和自动化失败，确认的核心崩溃或隐私问题先修。维护者日常自用和自动化结果分别记录；正式真机回归安排在预览发布后，不作为首发前置条件。
2. **收口本地开发线。** 上述检查通过后，将 `codex/android-dev` 快进到已验证的提交；本次不单独推送开发分支，也不合入 Windows 开发分支。
3. **整理独立的公开 `main`。** 皮肤设计参考原图和从图中直接提取的素材只留在本地，不随源码、APK 或发布附件公开。原图已进入旧提交，仅从最新文件树删除还不够；只在独立公开副本中排除这些素材，不改写本地开发历史。已获准公开的 61 张 Windows 验收截图不因这项限制移除。继续核对其他第三方材料的分发条件、署名、密钥和本机信息。词库不等人工复审，但仍须核对来源和再分发条件。
4. **构建并发布同一版本。** 从公开候选提交构建，使用[独立发行签名并复验最终 APK](android-public-preview.md)。对齐签名、SHA-256、源码与原生依赖源码；私钥不上传，未批准公开的原始验收报告不作为发布附件。推送前核对 `main` 和发布标签可达的所有提交，确认参考素材没有残留。只推送 `main` 和指向对应提交的 `android-v<versionName>` 标签，GitHub 先建草稿再发 **Pre-release**；注明兼容范围、已知限制和真机待补验。发布后将首页指向对应标签的 Release，不指向整个仓库的 `latest`。Windows 不创建 Release，之后独立使用 `windows-v<产品版本>`。

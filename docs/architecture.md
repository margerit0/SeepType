## 实际路径与补丁边界

Rime 全拼候选 → 简化字/去重 → Lua 精确查表 → ShadowCandidate 附加 comment → Weasel 双行布局。中文 text、顺序和原始候选不被改写；关闭学习或缺少释义时返回原候选。词表一次加载到内存，没有每键文件读取、联网查询或输入历史记录。

键盘英文动作位于 Lua processor：读取当前会话的真实选中候选，重新查表并检查开关、候选范围和光标位置。`Ctrl+Shift+Enter` 提交完整词表值，不从省略后的显示注释取文本。无释义、学习关闭、非完整组合时消费该专用动作且保留组合，避免回退提交拼音或丢字。空格、数字和普通点击继续选择中文。

原 [HorizontalLayout.cpp](https://github.com/rime/weasel/blob/0.17.4/WeaselUI/HorizontalLayout.cpp) 把 label/text/comment 横向排列，现有配置未提供本设计所需的上下两行。实验增加 `StudyLayout`，继承真实 StandardLayout，英文置于中文上方；整项共用高亮和点击区，长英文由 DirectWrite 单行省略。

[weasel-ui-spike.patch](../experiments/phase3/patches/weasel-ui-spike.patch) 对一个上游文件增加 **10 行**：7 行编译期开关选择新布局，3 行把本窗口已经生成的绘制缓冲区交给测试观察器。观察器只在明确的内部测试采样点写文件，不读取桌面；正常运行不采集画面。原 HorizontalLayout、librime 引擎和 IPC 均未修改。

学习状态在实验宿主中暂借注释颜色控制双行空间；这不是正式配置协议。实验外围按钮也不代表最终工具区或设置。阶段 4 已加入服务端会话版本和独立的 `study.v1` 跨进程动作协议，说明见 [study-ipc.md](study-ipc.md)。阶段 3 的 UI 补丁保持其原边界，新增 IPC 改动保存为另一份可审阅补丁。

### 暖态性能

同一次合成输入 `pingguo`，每组 300 个样本，统计包含输入解码和第一页候选生成，单位毫秒：

| 状态 | p50 | p95 | p99 |
| --- | ---: | ---: | ---: |
| 不含 Lua 扩展的基准 | 0.275 | 0.522 | 0.586 |
| 扩展加载、学习关 | 1.076 | 1.928 | 2.201 |
| 扩展加载、学习开 | 1.331 | 2.167 | 2.437 |

本轮接入共享 Lua 模块后重测，学习开与基准的 p95 相差约 1.65ms，低于实验设定的 2ms 参考目标。它不是单次查词耗时或普遍延迟保证；不能外推到大词库、所有输入和实际应用。词库扩充前仍需冷启动、内存和更多输入分布测量。

## 本次修复及维护要点

1. **ATL 初始化丢失**：本机 MSVC 下，同一编译单元包含 Rime API 头文件和 ATL 时，Rime 头文件的 `.CRT$XCU` 声明影响 selectany 初始化。最小对照中 ATL 的 cbSize/LockCount 从 44/-1 变为 0/0，注册窗口类时崩溃。将 Rime API 移入 `StudyEngine.cpp`，UI 只包含普通 C++ 数据接口后恢复；启动检查已覆盖。没有修改上游头文件，不推断官方完整构建也存在此问题。
2. **候选窗口生命周期**：Weasel 鼠标选词后销毁 popup，下一次组合必须重建。宿主按真实 Weasel 窗口类 atom 查找自身候选窗，不能把其他同线程输入窗口当成候选窗。
3. **只有样式变化时刷新**：缺词候选的 comment 始终为空，仅改变学习状态不会让 UI::Update 发现候选变化。宿主显式刷新布局和绘制，避免收起/展开失效。
4. **构建诊断**：本机 PDB 调试链接曾报 LNK1101；当前使用正常可构建的 /O2 或 /Od 加栈帧和 map 文件定位，不依赖该 PDB 路径。实验未进一步修改工具链。
5. **系统 IME 截走隔离宿主按键**：实际逐键输入时，现有系统 IME 抢先处理字母，宿主 Rime 无法接收。对宿主及子控件调用 `ImmAssociateContext(hwnd, nullptr)`，只取消本窗口关联；真实连续输入和新增内部断言均通过。这不是正式 TSF 的输入方案，也未改变默认输入法或系统设置。

## 阶段 4 第一批实现

共享代码在 `src/study`。`SessionVersion` 用会话身份与递增版本绑定短期菜单目标；输入、翻页、选中变化、开关、失焦均使旧目标失效，重建会话更换身份。`StudyEngine` 适配器在提交前重新读取当前 Rime 页、索引、拼音、光标和中文，再向 Lua 重新查询英文；菜单标签不作为提交数据。

共享 Lua `study_core.lua` 同时处理 Ctrl+Shift+Enter 与前端内部 `inspect-v1` / `commit-v1` 请求。请求使用会话临时属性及零键码，执行后清空请求，回复标记最后发布；查询不清除组合或领取提交。英文资格仍只在 Lua 中判断，正式模块不含实验 F8 绑定。学习开启时，缺词候选用空的 ShadowCandidate 注释隐藏其他上游注释，避免误当英文，原始候选仍保留。

原生菜单通过宿主对自己的 Weasel popup 安装 Win32 subclass 接入。菜单显示完整英文、明确的输入动作和禁用原因；候选行的普通左键继续提交中文。失活会关闭菜单、隐藏 popup 并使动作失效。16 项桌面观察已从两段中断聊天恢复，Shift+F10 经 `WM_CONTEXTMENU` 处理；来源和被测二进制与阶段 3 记录分开。

真实 Rime 会话的 20 项动作检查、既有 18 项引擎检查、28 项原生内部检查与 24 组布局测量均通过，本轮沿用结果。

## 阶段 4 服务会话与 IPC

`RimeSession` 绑定服务已有会话，不创建第二个引擎，也不领取 commit。`StudyService` 按 IPC 会话保存临时目标；服务实例随机身份、会话身份和递增版本共同防止旧动作跨重启或重建复活。客户端不传英文值。Inspect 查询 Lua 后返回完整释义与禁用原因；CommitEnglish 验证保存的目标，再由同一 Lua 实现重新决定并提交；SetLearning 立即使旧动作失效。

原 `WeaselClientImpl`、`WeaselServerImpl` 与 `RimeWithWeaselHandler` 已通过独立补丁接入这些动作；正常响应携带 capability 和版本，英文仍通过现有 commit 响应交付。查询及被拒请求不调用 get_commit，保留应用尚未领取的中文。输入、翻页、选择、开关、失焦、切换会话和维护结束都有失效接点。

新增管道覆盖同时修复四处边界：读取体实际在缓冲区零偏移；每次读取清除上一次响应；每个连接持有独立收发缓冲区；接受 ConnectNamedPipe 返回 ERROR_PIPE_CONNECTED 的已连接状态。通过真实不同进程运行，27 项检查通过，其中并发连接各连续输入 16 轮。

源码生成、固定依赖和运行方法见[阶段 4 说明](../experiments/phase4/README.md)，结果见 [service-ipc.json](../experiments/phase4/results/service-ipc.json)。没有重跑菜单、阶段 3 引擎或布局检查。该结果不代表 TSF 前端、可见服务窗口或实际应用兼容性已完成。
